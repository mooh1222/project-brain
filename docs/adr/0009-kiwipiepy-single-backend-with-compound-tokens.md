# 한국어 토크나이저는 kiwipiepy 단일 백엔드로 하고 어절 안 명사 결합형을 보존한다

색인과 질의가 공유하는 한국어 토크나이저는 pip으로 설치되고 버전이 고정된 kiwipiepy 하나만 쓴다. mecab-ko 우선 폴백 사다리를 없애고 정규식 분리는 테스트 주입 전용으로 남긴다. 형태소 조각에 더해, 같은 어절 안에서 연속한 명사 조각을 이어 붙인 결합형 토큰을 함께 보존한다(영문 심볼의 camelCase 조각과 원형 동시 보존과 같은 규칙). 색인 meta에 토크나이저 이름과 규칙 버전을 기록하고, 질의 시점의 값과 다르면 stale 색인과 같은 방식으로 거부한다.

mecab-ko 사전에는 프로젝트 복합명사가 없어 "인게임"이 "인"+"게임"으로, "럭키박스"가 "럭키"+"박스"로 쪼개져 개념 단위 토큰이 색인에 존재하지 않았다(객체 df 0). 2026-07의 어휘 명부 게이트는 이 토크나이저 공백을 위에서 우회한 것이었다. 사전에 없는 단어 옆에서 "이벤트"가 "이"+"벤트"로 갈라지는 문맥 의존 오분석도 있었고, kiwipiepy는 이를 바르게 분석한다. mecab은 brew 사전 경로에 묶여 있어 설치 유무에 따라 사람마다 다른 토큰이 나오며, 팀 공유 단계에서 색인과 질의의 비대칭 원인이 된다. 현행 코드는 색인과 질의의 토크나이저가 달라도 경고만 하고 검색을 계속하므로, 백엔드나 규칙이 바뀌면 옛 색인이 조용히 어긋난다. 결합형 보존은 BB2 객체 표면에서 "인게임" df 20, "럭키박스" df 27을 만들어 회수 층에서 문제를 직접 해결한다. 대가는 실모델 색인 rebuild 한 번과 골든셋 재기준이며, 사용자 사전·corpus 단어 추출은 이 결정에 포함하지 않는다.

## 보완 (2026-09-04, 규칙 버전 3)

BB2 재기준(pb#80) 뒤 두 가지를 같은 원칙("조각을 지우지 않고 표면을 더한다")으로 확장했다.

- 결합형 조각에 숫자(`SN`)·외국어(`SL`)를 허용한다. 원안의 태그 목록에 있었지만 "모든 조각이
  한글 포함" 조건 때문에 실제로는 참여하지 못하던 죽은 가지였다. 조건을 "한글 조각 하나 이상"으로
  바꿔 `3단계`·`2차`·`ui버튼`이 토큰으로 남고, 한글 없는 `3.7new`는 심볼 경로에 맡긴다.
- 동사 어간과 명사형 전성어미(`ETN`)가 한 어절에서 이어지면 원문 표면(`알림`·`만들기`·`보여주기`)을
  토큰으로 보존한다. kiwi가 `알림`을 문맥에 따라 명사 또는 `알리`+`ㅁ`으로 달리 읽어 색인과 질의가
  어긋나던 문제(BB2 객체 118건 중 17건이 `알림` 토큰 없이 색인)를 사용자 사전 없이 흡수한다.

둘 다 산출 토큰이 늘어나므로 `TOKENIZER_RULES_VERSION`을 3으로 올렸고 소비 프로젝트는 rebuild가
필요하다. 사용자 사전·오타 교정은 여전히 범위 밖이다.

## 보완 (2026-09-04, 규칙 버전 4)

명사류 연속 뒤에 바로 붙은 파생 접미사(`XSN`)를 같은 결합형에 포함한다(#82). kiwi는 `시간제`를
시간(`NNG`)+제(`XSN`)로 읽어 규칙 3까지는 접미사에서 연속이 끊겨 `시간제`·`스테이지별`·`이벤트용`·
`활성화` 토큰이 색인에도 질의에도 없었다 — pb#81(ingame-item-usage migration)에서 "시간제 아이템"
질의가 `시간`(df 113)·`제`(43) 조각으로만 매칭돼 필수 mapping이 경쟁 term 87개가 빠진 뒤에야 8위로
들어온 것이 계기다. 접미사는 이미 시작된 연속을 확장만 하고 시작하지는 못하므로(대명사 뒤 `우리들`은
결합형 없음) 원칙("조각을 지우지 않고 표면을 더한다")은 그대로다. 산출 토큰이 늘어나므로
`TOKENIZER_RULES_VERSION`을 4로 올렸고 소비 프로젝트는 rebuild가 필요하다. BB2 GlossaryTerm 표면
1,098개 중 해당 어절은 16개다.
