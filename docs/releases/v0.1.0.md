# Project Brain v0.1.0

엔진 저장소를 clone하지 않고 설치할 수 있는 첫 release다(#107). 엔진 기능은 이 tag가
가리키는 커밋의 `main`과 같고, 배포 방식만 새로 생겼다.

## Artifact

| 파일 | 내용 |
|---|---|
| `project_brain-0.1.0-py3-none-any.whl` | 엔진 패키지 + `project-brain` CLI + 설치 스킬 템플릿 전체(실행 비트 보존) |
| `project-brain-0.1.0-constraints.txt` | 엔진 `uv.lock`의 runtime 해석 결과(개발 의존성·엔진 자신 제외, 모든 항목 `==` 고정) |
| `SHA256SUMS` | 위 두 파일의 SHA-256. `shasum -a 256 -c SHA256SUMS`로 확인 |

## 소비자 설치

```bash
V=0.1.0
BASE=https://github.com/mooh1222/project-brain/releases/download/v$V
uv tool install "$BASE/project_brain-$V-py3-none-any.whl" \
  --constraints "$BASE/project-brain-$V-constraints.txt"
project-brain --version   # project-brain 0.1.0
```

그다음 프로젝트 루트에서 `project-brain install --project <이름>` 또는
`project-brain bootstrap`을 실행한다. 사용법은 README의 "프로젝트에 붙이기" 절과 같다.

## 업그레이드·rollback

- 업그레이드: `V`를 새 release로 바꿔 위 설치 명령을 다시 실행한다.
- rollback: `V`를 이전 release로 바꿔 같은 명령을 실행한다. 제거 없이 교체된다.
- editable 설치에서 전환할 때도 같은 명령이면 된다. 되돌리려면 `uv tool install -e <엔진 클론>`.
- 엔진을 바꾼 뒤 이미 주입된 스킬을 갱신하려면 프로젝트에서 `project-brain install`을 다시
  실행한다. 사용자가 고친 관리 파일은 건너뛴다(`--force`로만 덮는다).

## 엔진 개발자 설치

엔진을 고치거나 적재를 운영하는 사람은 기존처럼 clone 뒤 `uv tool install -e ./project-brain`을
쓴다. 코드 수정이 즉시 반영되고, 아래 제약 경로가 모두 동작한다.

## 제약: 엔진 git checkout이 필요한 경로

release 설치본은 site-packages에서 import되므로 엔진의 git HEAD를 확인할 수 없다. 다음은
엔진 checkout을 요구하며 release 설치본에서는 실패한다(조용히 넘어가지 않고 오류로 끝난다).

- `ingest --batch-binding-file …`과 설치 스킬의 `scripts/run_ingest_batch.py`(batch ingest):
  실제 engine HEAD를 선언된 `engine_sha`와 대조한다.
- `migration` 계열(`quote-debt build`, `--engine-root`를 받는 명령)과 `snapshot create --engine-root`.
- 설치 스킬의 `scripts/validate_foundation.py`와 foundation 검증: 로드된 엔진 코드가 지정된
  checkout 안에 있어야 한다.

`install`, `bootstrap`, `doctor`, `search`, `show`, `query`, `index`, `eval`, `lint`, `build`,
`graph`, `draft`, `session`, `stale-check`, 단건 `ingest`·`promote`·`promote-auto`·`mark-checked`·
`projection refresh`·`context-replace`는 checkout 없이 동작한다. `--engine-sha`를 받는 쓰기
명령은 값의 형식만 검사하므로, release 설치본에서는 이 tag가 가리키는 커밋 SHA를 넘긴다.

## 검증

release 전에 `tools/release.py build`·`smoke`로 확인하고, 게시 뒤 `smoke --from-release`로
release URL에서 다시 확인한다. 확인 항목은 다음과 같다.

- 깨끗한 HEAD(`git archive`)에서 빌드. wheel의 템플릿 집합과 실행 비트가 tag 커밋과 일치
- constraints는 `uv export --locked`(lock이 pyproject와 어긋나면 실패), 전 항목 고정
- 격리된 tool 환경에 깔린 엔진 파일이 checksum으로 검증한 wheel과 같음(RECORD 해시), 의존성
  버전이 constraints와 일치
- 설치본의 `--version`·`--help`, `project_brain` import 위치가 tool 환경 안(source checkout 아님)
- 임시 프로젝트에 `install` 2회: 두 번째 보고의 `created/updated/removed/adopted/skipped`가 모두 빈 배열
- 주입된 스킬 파일의 실행 비트가 원본 템플릿과 일치

범위 밖: PyPI·사내 registry 게시, standalone 실행 파일, 자동 release CI, 다중 OS matrix,
임베딩 모델·색인 배포.
