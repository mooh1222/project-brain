# Project Brain v0.2.0 — 게시 및 다운로드 검증 완료

#113의 release-only 일반 팀 적재 지원과 현행 JSON v2 초안을 포함하는 다음 minor 버전이다.
커밋 `c43c46f2e35b7a9b0ecf4d92c7e516d74319e994`에서 정식 wheel을 빌드하고
격리 설치·공개 소비자 smoke를 통과했다. 같은 commit을 가리키는 `v0.2.0` tag와
[release](https://github.com/mooh1222/project-brain/releases/tag/v0.2.0)를 게시한 뒤, 공개 URL의
wheel·constraints·checksum을 다시 다운로드해 같은 검증을 통과했다. **엔진 E3 완료**이며
실제 소비 프로젝트의 최종 통합 검증은 별도다.

## Artifact와 설치

기존 배포 절차의 `tools/release.py build --tag v0.2.0`으로 커밋된 HEAD만 빌드했다.
검증된 로컬 산출물은 다음과 같다. 이 문서는 후속 문서 커밋에서 기록하며 artifact의
source commit은 위 빌드 커밋으로 유지한다.

| 대상 | SHA256 |
|---|---|
| `project_brain-0.2.0-py3-none-any.whl` | `f6ec9863d872c95c9385aa51efe8663b2fa2bcc7cf0ceea6b5b90de7a7a5fd3a` |
| `project-brain-0.2.0-constraints.txt` | `f51f915a3dc1be9c817debc41a42d4d374beb18e9803eb76aedb4bb715d40425` |
| `SHA256SUMS` | `7ec191e96769238ef65f7408649f20460bf4328e5f07b5dbf5939a469537bac2` |
| package content identity | `6242d595b4607ca8199edf3d968563fff8b54bcb0de1d23d0f4ba194017e474a` |

게시 URL의 세 파일은 위 로컬 검증본과 SHA256이 모두 일치했다.
`tools/release.py smoke --tag v0.2.0 --from-release`가 격리 import, wheel/constraints 일치,
installer 65개 파일의 두 번째 무변경 및 공개 batch·receipt·재실행·복구·거부 경로를 확인했다.
JSON v2·조회·감사·세션도 통과했다. 소비 프로젝트의 버전 고정·데이터 통합 검증은 그쪽 작업이다.

```bash
V=0.2.0
BASE=https://github.com/mooh1222/project-brain/releases/download/v$V
uv tool install "$BASE/project_brain-$V-py3-none-any.whl" \
  --constraints "$BASE/project-brain-$V-constraints.txt"
project-brain --version
project-brain --engine-identity
project-brain install --project <project> --default-branch <branch> --repo <repo-id>
```

checksum 파일과 wheel·constraints를 다운로드해 SHA256을 먼저 검증한다. 격리된 프로젝트별
tool 설치도 가능하다. CLI와 scripts가 같은 설치본을 쓰도록 PATH와 PROJECT_BRAIN_PYTHON을
그 tool 환경으로 지정하고 PYTHONPATH/PYTHONHOME을 제거한다. 전역 설치 변경은 필수가 아니다.
installer가 skipped로 보존한 실행 scripts는 diff를 검토한 뒤 갱신한다. 프로젝트 overlay와
사용자 파일을 강제로 덮지 않는다. 두 번째 깨끗한 설치의 변경 배열은 모두 빈 목록이어야 한다.

## 내용 신원과 실제 실행

build는 원본 commit과 version, 패키지 파일 전체의 SHA256·실행 비트 목록을
`project_brain/_release_identity.json`에 넣는다. `engine_identity`는
`scheme=release-v1`, `version`, `source_commit`, `content_sha256` 네 필드다.
digest는 목록과 출처의 canonical JSON 해시다. wheel checksum은 배포 artifact 자체를,
이 신원은 실제 설치한 엔진과 템플릿의 내용을 검증한다. 신뢰하는 release 출처를 대체하는
서명 기능은 아니다. 의존성 버전은 기존 constraints와 설치 smoke가 따로 확인한다.

`--engine-identity`가 반환한 `engine_sha`와 `engine_identity`를 batch manifest에 함께 넣는다.
`engine_sha`는 원본 Git commit 의미를 유지한다. 같은 version이라는 이유로 다른 내용의
설치를 허용하지 않는다. 실제 import/distribution 위치, 파일 내용·실행 비트, 로드 모듈의
출처와 메모리에 기록한 실제 실행 module code/source 일치를 검사한다. 캐시 삭제·재생성으로
이 관측을 바꾸지 못하며 설치 runtime helper도 source를 직접 읽어 실행한다.
로드된 설치 root와 device/inode도 report/binding에
결속한다. 입력·coverage·소비 revision은 엔진 신원과 별도 결속이며 그대로 유지한다.

정상 실행은 기존 canonical mutation/no-op receipt와 durable intent/journal을 사용한다.
runner의 시작/item/finalizer 전후와 CLI/MutationService 쓰기 직전에서 재검증한다.
설치 runtime의 실행 scripts도 현재 엔진의 렌더 결과와 대조한다.

## 호환·재실행

| 실행 | 지원 |
|---|---|
| 기존 checkout manifest/receipt + 같은 checkout/root | 기존 계약 유지 |
| legacy checkout manifest/receipt + release 설치 | 동일성 증명 불가, 무쓰기 거부 |
| 새 release manifest + 같은 내용·원본 commit·runtime·root | 적재·정상 재실행·부분 재개 지원 |
| 같은 version이나 내용/실행 비트/원본 commit 불일치 | 쓰기 전 거부 |
| 입력·coverage·소비 revision 불일치 | 기존 결속 검증에 따라 거부 |
| 단계 사이 엔진 변경 | 다음 검증 경계에서 거부. 이미 커밋된 item receipt는 보존 |
| 변경된 엔진 그대로 재개 | 무쓰기 거부 |
| 원래 엔진/runtime 복원 후 동일 root·입력에서 재개 | 완료 receipt를 복구하고 pending item만 실행 |
| 소비 경로·brain inode 또는 엔진 root/inode 변경 | 과거 실행 재개 불가. 원본 보존 후 새 실행 준비 |
| pre-coverage 역사 binding | 기존 명시적 읽기 전용 recovery만 유지 |

완료/부분 report에는 `run_ingest_batch.py batch.json --report report.json --resume report.json`을
사용한다. manifest나 receipt를 수기 패치해서 이관하지 않는다. receipt 없는 기존 데이터가
있으면 일반 검토·build precondition으로 새 실행을 준비해야 하며 자동 재개로 가장하지 않는다.

세션 추출의 정식 적재는 같은 batch/finalizer를 사용하고 `session complete`로 transcript와
canonical receipt를 결속한다. `audit`에는 엔진 checkout이 필요 없다. 조회는 fresh index가
필요하다. JSON v2 create/list/show/update/prepare와 기존 Markdown v1 읽기도 포함한다.
Foundation P0 gate와 일반 migration/snapshot의 checkout 요구는 유지한다.

검증 상태와 승인 경계는 [로컬 실행 보고서](../reports/2026-10-22-release-team-ingest.md)를 본다.
