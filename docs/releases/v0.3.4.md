# Project Brain v0.3.4 — 게시 및 다운로드 검증 완료

[#119](https://github.com/mooh1222/project-brain/issues/119)의 공개 raw 청크 미리보기와
[#120](https://github.com/mooh1222/project-brain/issues/120)의 Python 3.13 순환 링크 진단 수정을
소비 프로젝트가 설치할 수 있도록 묶는 패치 릴리스다.

## 포함 변경

- `project-brain raw chunk-preview [--brain-root <경로>] [--json] [paths…]`는 실제 rebuild와
  원문 발견·청크 분할·검색 토큰 공백 제외를 공유해 원문별·합계 예상 raw 색인 행 수를 제공한다.
  빈 원문은 0행으로 보고하며 코퍼스·색인을 쓰거나 임베더를 로드하지 않는다.
- 순환 심볼릭 링크는 Python 3.11~3.13에서 `manifest_local_path_invalid`로 분류한다.
  정상 파일·누락 파일·broken link·root escape·NUL 경로의 기존 진단을 보존한다.
- 설치 스킬 2개에서 고정 raw 청크 수를 손으로 갱신하라는 안내를 정리하고 새 미리보기와
  소비 프로젝트 가드 전환의 관계를 설명한다.
- 의존성·schema·청크 경계·tokenizer·검색 입력·색인 형식은 바꾸지 않는다. 이 release 채택만으로
  코퍼스 migration이나 실모델 색인 rebuild를 요구하지 않는다.

## release 검증

- `uv lock --check`와 release/CLI version 표적 검사 **37 passed**, `git diff --check` 통과.
- Python 3.12를 선택한 로컬 및 공개 `tools/release.py smoke --tag v0.3.4 --from-release`
  검증이 통과했다(로컬에서는 `--from-release` 생략). wheel·constraints·실행 비트·release
  신원·격리 import 위치를 확인하고 관리파일 **66개**와 두 번째 설치의
  `created/updated/removed/adopted/skipped`가 모두 비어 있음을 확인했다.
- 합성 소비자의 batch·재실행·부분 재개·receipt·JSON v2·audit·session과 잘못된 입력의
  무쓰기 거부를 확인했다. 임베더는 stub, tokenizer는 정규식 주입이며 실모델 검증이 아니다.
- 공개 URL에서 세 artifact를 별도로 내려받은 SHA-256이 로컬 산출물 및 GitHub asset
  digest와 일치했다. 공개 wheel의 Python 3.12 격리 설치에서 preview의 known literal
  **2/0/0/3, 합계 5**와 임베더 import·DB 연결·쓰기 차단, 코퍼스 불변성을 확인했다.
- 검증한 공개 wheel의 파일·실행 비트·배포 metadata를 보존해 읽은 별도 Python 3.13.6
  프로브도 실제 순환 링크를 `manifest_local_path_invalid`로 진단했다. 무결성 검사는 유지했다.
- v0.3.3 대비 관리파일 추가·삭제는 없고 변경은 `ingest/references/ingest-tools.md`와
  `session-ingest/SKILL.md` 두 개다. 실행 runtime 6개는 bytes·실행 비트가 같다.


## 소비 프로젝트 반영

- BB2 같은 고정 release 소비자는 새 wheel·constraints·checksum으로 pin을 갱신한다.
- 독립 청커가 있는 실코퍼스 가드는 공개 미리보기의 `raw_chunks`로 기대값을 대체하되,
  원문 추적·manifest locator 존재 검사와 빈 원문 거부는 유지한다.
- 팀 스킬 사본과 installer manifest는 각 소비 프로젝트의 overlay 보존 절차로 갱신한다.
  엔진 release 게시만으로 BB2 전환이나 BB2 실코퍼스 검증까지 완료됐다는 뜻은 아니다.
