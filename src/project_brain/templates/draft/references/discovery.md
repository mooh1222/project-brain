# 관련 초안 발견과 읽기 전용 참고

일반 질문·개발 착수 또는 세션 재료 작업을 시작하면 search/네 query 축 분기 전에 실행한다.
같은 작업을 분해한 질의마다 반복하지 않고 새 작업 범위나 재개 시 한 번 확인한다.

```bash
project-brain draft list
```

## 목록 해석과 선택

- `drafts`의 topic ID·제목·scope·갱신 시각·format으로 관련성을 판단한다.
  `scope`는 최대 240자 미리보기이며 `scope_truncated=true`면 뒤가 생략됐다.
- `diagnostics`는 읽을 수 없거나 형식이 잘못된 파일의 경로·문제 코드다.
  `partial=true`면 정상 목록을 사용하되 전체 초안을 확인한 결과처럼 말하지 않는다.
  모든 파일에 문제가 있어 `drafts=[]`여도 초안 부재로 판정하지 않는다.
- 루트 경로·접근 오류는 **발견 실패**다. 정상적인 빈 목록과 구분해 알린다.
  초안 발견이 실패해도 가능한 Brain 조회는 계속하되, 초안까지 조회했다고 말하지 않는다.
- `json-v2`는 기본 show의 요약·목차 뒤 `show <topic-id> --item <key>`로 필요한 항목과
  참조 source를 읽는다. 요약만으로 본문 사실에 관한 답을 끝내지 않는다.
- `markdown-v1`은 `project-brain draft show <topic-id>`로 전체 본문을 읽는다.
  여러 읽기 후보는 metadata로 좁히고 답에 필요한 본문만 연다. 읽기 전용 조회를
  사용자 topic 선택 대기로 중단하지 않는다. 갱신할 topic이 모호하면 draft 스킬에서 선택받는다.
- 발견 범위는 **topic 단위**다. metadata에 없다고 다른 topic 내부에도 지식이 없다고
  단정하지 않는다. 매 질문마다 전체 본문을 검색하거나 새 색인을 만들지 않는다.

## 답변에 사용하는 방법

- 초안에서 가져온 내용은 **초안(미검수 작업 기억)**으로 표시하고 topic·갱신 시각·확인한
  근거를 붙인다. 초안 파일 자체를 정식 Brain 객체나 원문 근거로 취급하지 않는다.
- Brain 부재 판정은 기존 Brain 조회 결과로 한다. 초안에만 있으면
  **Brain 객체로는 회수되지 않았고 초안 기록은 있음**으로 구분한다.
  색인 없음/stale 같은 **조회 실패**는 부재가 아니다. 목록 조회는 색인 없이 가능하지만
  그것이 Brain 조회 성공을 뜻하지는 않는다.
- reviewed 객체와 초안이 충돌하면 양쪽 주장·갱신 시각·근거를 병기한다.
  최신 시각만으로 우선하지 않는다. 원문 대조에 따른 판단은 별도 근거와 함께 설명할 수 있다.
- 조회만으로 객체·초안을 수정·승격하지 않는다. 기록·적재는 해당 쓰기 요청의 절차로 넘긴다.
