# 목적별 기록·회상 판단

query·draft·session-ingest·ingest가 함께 읽는 판단 정본이다. 사용자는 저장 종류나 객체 kind를
고르지 않는다. 요청의 목적·자료·작업 맥락으로 필요한 경로만 사용하며, 기존 기록 권한 안에서
처리한다. 자료나 갱신 대상이 실제로 모호할 때만 확인한다.

| 목적 | 기록 | 회상 |
|---|---|---|
| 지식 초안 | 주제별 이해·출처·가설·결정·미결을 draft에서 이어간다 | [초안 발견](discovery.md)으로 좁혀 필요한 본문·출처를 읽는다 |
| 적재 지식 | 충분히 확인된 내용을 기존 ingest로 구조화한다. Insight도 기존 적재 지식이다 | search → 핵심 show. 관련 reviewed Insight는 advisories의 근거·적용 범위를 확인해 주의사항으로 곁들인다 |
| 개선 제안 | 나중에 검토할 구체적인 개발 개선 행동을 기존 백로그에 제안으로 보존한다 | query의 직접 읽기 분기로 해당 본문·출처·확인 한계를 읽는다 |

원문은 이 지식의 근거층이다. 에이전트가 해석한 요약·가설·제안을 `{{BRAIN_ROOT}}/raw/sources/`의
실제 원문과 섞지 않는다. 후보 객체와 초안도 다르다. 객체 종류와 검수 상태는 별도 축이며,
기존 candidate/reviewed 계약을 유지한다. 초안은 **초안(미검수 작업 기억)**, candidate는
**확인 필요**, raw는 **원문 발췌**로 표시하고 reviewed 객체에서 확인한 내용과 구분한다.

## 기록과 정식화

- 기능뿐 아니라 도메인·조사 주제도 초안으로 이어갈 수 있다. 유용한 주제·출처·재개 가치가
  있으면 단건도 허용한다. 모든 미정리 생각이나 작은 작업에 새 초안을 강제하지 않는다.
  확인된 이해와 가설·열린 질문·한계를 구분한다.
- 충분히 확인된 내용의 직접 적재 요청은 기존 ingest로 처리한다. 초안 생성이나 검증 대기
  등록은 필수 선행 단계가 아니다. 형식·quote·hash 확인은 의미 검증이나 적재 승인이 아니다.
- Insight의 근거 객체·source 개수·reviewed-only 조건은
  [객체 모델](../../{{PROJECT}}-brain-ingest/references/object-model.md#insight-적재-규칙)이 소유한다.
  단일 동작 설명은 해당 기존 객체로 적재한다. 함께 수정할 때의 위험·교훈과 “공통화하자”는
  개발 개선 행동을 구분한다. 근거 부족은 해당 초안의 한계·열린 질문 또는 기존 적재의 보완
  사항으로 남긴다. 근거 객체를 먼저 적재해야 한다는 이유로 개발 개선 백로그에 보내지 않는다.
- 이해와 개선 행동이 섞인 요청은 필요한 지식과 행동을 나누고 출처로 연결한다.
  자동 이동이나 같은 사실의 이중 기록은 하지 않는다.
- 정식화는 실제 원문과 대조하고 기존 검수·coverage·최종화 절차를 따른다. 초안과 준비 packet을
  원문이나 적재 승인으로 사용하지 않는다. 적재 뒤 draft의 기존 SHA 기반 갱신으로 적재 객체
  참조와 남은 미결을 반영한다. 자동 전체 승격·close·삭제나 별도 적재 장부를 만들지 않는다.
- 적재 성공 뒤 초안 갱신이 충돌하면 성공한 적재와 남은 초안 정리를 구분해 보고한다.
  최신 초안을 읽어 기존 갱신 Interface로 보완한다. 같은 내용을 무조건 재적재하거나 두 효과를
  새 복합 transaction으로 묶지 않는다.

## 개선 제안의 보존과 직접 읽기

기존 기록 위치는 `{{BRAIN_ROOT}}/backlog/development.md`다. 프로젝트 소유 저장 규약이 있으면
함께 따른다. 경로는 `.project-brain.json`이 해석한 Brain 루트를 사용한다. 상대 경로는 config가
있는 프로젝트 루트 기준이며 특정 개인 경로·브랜치·설치 위치를 전제하지 않는다.

쓰기 전에 Git 추적 상태와 기존 내용을 확인해 보존하고, 허용된 기록 요청에서만 필요한 부모
디렉터리를 만든다. 항목은 다음 정보를 남기며 **제안, 실행 확정 아님**을 표시한다.

- 날짜·요약, 문제·기대 효과
- 출처·검증 한계
- 실제 실행으로 채택된 경우에만 이슈·작업 링크 한 줄

`진행 상태: 미착수/진행 중/완료/보류` 필드는 제거한다. 채택 여부를 위한 별도 상태 필드도
만들지 않는다. 진행은 링크 대상이 소유하며 백로그에서 진행표를 복제하지 않는다.
백로그는 **비색인**이고 Project Brain snapshot 대상이 아니므로 이 파일만 바꿨다면 rebuild는
필요 없다. 새 schema·CLI·검색 채널을 추가하지 않는다.

“전에 ~하자던 거”, “남은 개선”처럼 개선 제안을 묻는 요청은 실제 백로그 본문을 직접 읽는다.
개선 제안만 묻는 경우 전체 초안 목록이나 일반 지식 검색을 필수 선행하지 않는다. 혼합 요청은
필요한 경로만 조합하고 각각의 출처를 구분한다. 기록 날짜·출처·제안 여부·채택 링크와 현재
확인 한계를 제시한다. 기록 존재나 과거 미착수 표시는 현재도 미해결이라는 증거가 아니다.

엔진은 백로그 파일을 scaffold하지 않는다. 설정된 Brain 루트를 해석하고 접근 가능 여부를
확인한 뒤 파일이 없으면 **해당 저장 위치의 정상 빈 결과**다. 조회 중 파일을 생성하지 않는다.
루트 해석 실패·권한 오류·불완전 조회는 파일 부재와 구분해 알린다.

## 조회·호환·설치 경계

- 일반 지식 질문·개발 착수·재개는 [초안 발견](discovery.md)과 기존 search → show를 따른다.
  같은 작업 범위의 분해 질의마다 전체 초안 목록을 반복하지 않는다. 초안의 관련 본문·출처를
  읽고, reviewed 객체와 충돌하면 주장·출처·갱신 맥락을 병기한다. 최신 시각만으로 우선하지 않는다.
- 목록 불완전·접근 실패·도구 미준비·색인 오류는 정상 빈 결과가 아니다. 가능한 조회는 계속하되
  실패한 범위까지 확인했다고 말하지 않는다. 조회만으로 파일·객체·검수 상태·색인·stale cache·
  Git 상태를 바꾸지 않으며 자동 설치·rebuild도 하지 않는다.
- `{{BRAIN_ROOT}}/pending/insights.md`는 **기존 검증 대기 기록**이다. 기본 신규 기록 경로에서
  제외한다. 유용한 주제의 미검증 관찰은 해당 초안의 이해·가설·질문과 출처·한계로 관리한다.
  기존 파일·항목·이력은 보존하고 명시적 과거 기록 조회에서는 실제 본문을 읽어 **기존 기록·
  미검증**으로 표시한다. 자동 적재·이동·삭제하지 않는다. 이 영역도 비색인·snapshot 밖이다.
  다른 기능의 pending 상태나 적재 보고서의 보류 필드를 일괄 폐기하지 않는다.
- 기존 초안 형식은 강제 변환하지 않는다. 원문 출처 보존과 새 합성 지식 생성도 구분한다.
- 사용자 수정으로 설치가 skipped된 파일과 비관리 overlay는 보존한다. 새 지침이 적용되지 않은
  범위를 보고하고 설치 실행 자체를 의미 동작의 성공으로 표시하지 않는다.
