# 변경 이력 판정

변경 이력에서 새 사실이나 결정이 기존 지식과 만날 때, 대체·보완·충돌 중 하나를 사람이 판정한다.
코드는 연결·형식·충돌 신호를 검사할 뿐 의미 결론을 대신 내리지 않는다.

## 대체

같은 subject와 predicate의 새 값이 옛 값을 더 이상 유효하지 않게 만들고,
어느 값이 현재 정답인지 근거로 확정할 수 있으면 대체다.

- 옛 객체를 `superseded`로 바꾸고 새 객체가 무엇을 대체하는지 연결한다.
- 변경 사실과 이유는 EventLedgerRecord 또는 DecisionRecord로 남긴다.
- 대체 뒤에도 옛 근거와 당시 값을 지우지 않아 이력 질의가 따라갈 수 있게 한다.

예: 참여 조건의 값이 A에서 B로 바뀌고, 현재 사양과 변경 근거가 B를 확정한다.

## 보완

기존 사실을 무효화하지 않고 새 예외, 운영 이유, 추가 규칙, 확인 가능한 맥락을 더하면 보완이다.
새 DecisionRecord나 사실을 기존 매핑에 연결하되 기존 객체를 supersede하지 않는다.

예: 기존 참여 조건은 그대로이고, 특정 기간에만 적용되는 추가 제한이 생겼다.

## 충돌

같은 subject와 predicate에 서로 양립할 수 없는 값이 있는데,
어느 쪽이 현재 정답인지 근거로 확정할 수 없으면 충돌이다.

- 둘을 임의로 지우거나 대체 처리하지 않는다.
- 충돌 신호와 근거를 남기고 사용자 또는 권한 있는 소스의 확인을 기다린다.
- 확인 뒤에만 대체 또는 보완으로 정리한다.

예: 현행 문서와 운영 기록이 서로 다른 값을 말하지만 적용 시점이 확인되지 않는다.

## 판정 기록

판정마다 새 근거, 영향을 받는 객체, 확인한 경계, 남은 불확실성을 남긴다.
근거가 같은 사실을 반복할 뿐이면 새 객체를 만들지 않고 기존 연결을 보강한다.
판정이 애매한데 적재 일정만 급하면 candidate로 감추지 말고 충돌로 남긴다.
