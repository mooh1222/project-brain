# 적용 범위와 상태축

이 스킬은 완료된 기능 또는 확정된 도메인을 Brain에 소급 적재하는 경우에만 쓴다.
진행 중 개발에서 후보를 선점하는 흐름과 끝난 세션 로그를 채굴하는 흐름은 이 스킬 범위가 아니다.

## 적용 시나리오

완료 소급 적재는 현재 코드와 문서가 안정돼 있어, 확인한 심볼을 {{DEFAULT_BRANCH}} 기준으로 앵커할 수 있을 때 시작한다.
기능 단위와 여러 기능을 가로지르는 도메인 단위는 모두 이 시나리오에 들어갈 수 있다.
둘의 차이는 Context 경계와 소스 묶음의 크기이지 완료 상태의 정의가 아니다.

다음은 멈추고 다른 흐름이나 사용자 확인으로 넘긴다.

- 코드가 계속 바뀌는 진행 중 개발
- 머지 뒤에도 유지되지 않을 수 있는 임시 코드 앵커
- 원문 소스 없이 끝난 세션 대화만으로 하는 지식 채굴

## 세 상태축

세 축은 서로 다른 질문에 답한다. 하나를 다른 축의 완료 증거로 쓰지 않는다.

| 축 | 뜻 | 확인하는 질문 |
|---|---|---|
| `feature_done` | 기능이 소급 적재를 시작할 만큼 완료된 외부 상태 | 지금 적재를 시작해도 되는가 |
| `current_ingest_done` | 현재 코드와 현행 소스로 현재 사실을 적재·검수한 상태 | 무엇이고 어디서 어떻게 동작하는가 |
| `history_coverage` | 변경 이력 소스를 확인한 범위 | 왜 바뀌었고 당시 무엇이었는가 |

`feature_done`은 사용자 선언, QA·출시 맥락, 이슈 상태로 판단한다.
이력 시스템의 자료가 없다는 사실만으로 기능이 미완료가 되지는 않는다.

`current_ingest_done`은 현재 {{DEFAULT_BRANCH}} 코드와 현행 소스가 확인됐는지를 말한다.
검수 상태는 현재 사실에 대한 검수이며, 이력 확인 범위와 같은 값이 아니다.

`history_coverage`는 아래 허용값 중 정확히 하나로 기록한다.

- `history_coverage=unsearched`: 현재 사실만 확인했고 이력은 찾지 않았다.
- `history_coverage=partial`: 일부 이력만 확인했으며 빠진 범위를 함께 알린다.
- `history_coverage=complete`: 알려진 변경 묶음을 EvidenceRef로 다시 확인해 연결했다.

`history_coverage=complete`가 아니면 변경 이유나 당시 상태를 완결된 답으로 말하지 않는다.
반대로 이력이 비어 있어도 현재 사실 적재와 검수는 완료될 수 있다.

## 머지 전·후 경계

커밋 SHA는 한번 만들어지면 바뀌지 않는다. 코드 앵커는 {{DEFAULT_BRANCH}} 이력에서 도달 가능한 commit SHA와
확인한 심볼을 쓴다. fast-forward와 일반 merge에서는 작업 브랜치의 기존 커밋과 SHA가 {{DEFAULT_BRANCH}}
이력에 그대로 포함되므로, 머지했다는 이유만으로 {{DEFAULT_BRANCH}} 끝의 새 SHA로 교체하지 않는다.

머지 전 PR HEAD를 임시 앵커로 썼다면 머지 뒤 `git merge-base --is-ancestor <commit_sha> <{{DEFAULT_BRANCH}}-ref>`로
기존 SHA가 {{DEFAULT_BRANCH}} 이력에서 도달 가능한지 확인하고, 앵커 대상 코드도 다시 대조한다. 둘 다 유지되면
기존 SHA를 그대로 쓴다. squash·rebase·cherry-pick 또는 충돌 해결로 기존 SHA가 {{DEFAULT_BRANCH}} 이력에 없거나
코드가 달라진 경우에만 {{DEFAULT_BRANCH}}에서 다시 확인한 commit SHA와 스냅샷으로 갱신한다.

이 경계는 객체 ID가 살아 있어도 실제 코드를 가리키지 못하는 조용한 손상을 막는다.
작업 브랜치 SHA라는 이유만으로 버리거나, 새 {{DEFAULT_BRANCH}} 끝의 SHA라는 이유만으로 교체하지 않는다.
